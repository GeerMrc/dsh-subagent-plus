# 0003 — 候选模型清单即官方「模型选择」的完整替代（移除官方授权清单编辑面）

日期：2026-10-29 ｜ 状态：已实施（v0.3.2，用户实测反馈裁定）｜ 关联：[0001](2026-10-29-takeover-surface.md)（其决策 2 中"授权清单同键编辑"部分被本决策取代）、[0002](2026-10-29-takeover-v0.3.1-refinements.md)（其 D3 版本线由 0.3.2 续接）

> 状态更新：本决策的两条只读桥接（autoRoute 采纳官方第一条、空候选回落官方池）已被 [0005](2026-10-30-binary-takeover.md) 取代——官方授权清单零引用；「候选清单 = 完整替代」的编辑面结论不变并升格为唯一路由来源。

## 背景

v0.3.1 把官方「子智能体」设置页的两个区（运行限制、模型选择授权清单）都搬进了本插件设置页（0001 决策 2 的"编辑面吸收"）。用户实测后裁定定位：**候选模型清单（策略 + 逐模型推理强度 + 兜底 + 健康冷却）就是官方「模型选择」的完整且更高级的替代**——再放一个「官方授权清单」编辑区，等于把被替代品的旋钮搬回来，制造"两个清单"的迷惑。运行限制则不同：它是 v0.0.2 缺失、接管所必需的功能面，保留（v0.3.2 起并入候选清单同一张卡顶部，不再用独立边框切断）。

## 链路核实（为什么移除编辑面不损失接管能力）

官方 `subagent-model-selection-settings`（enabled + allowedModels）在运行时只有三个作用：

1. **逐次显式指派白名单**：约束主智能体在委派调用里显式指定的 provider/model。本插件默认 `respectExplicit=false`，`agent/request` 瀑布在官方解析**之后**整体改写路由——白名单的放行结果直接被覆盖，接管态下对最终路由没有决定权。
2. **autoRoute 数据源**：钉定路由留空且开 autoRoute 时采纳官方清单第一条（`src/pin.ts` `resolvePinRoute`）。
3. **空候选回落池**：轮询/随机策略清单为空时以官方清单为候选池（`src/strategy.ts` `candidateRoutes`）。

2/3 是本插件 host 半边对官方命名空间的**只读桥接**，不是用户需要管理的编辑面；1 在默认配置下被覆盖。因此：**移除的只是编辑面，桥接与官方运行时行一律保留**（takeover-patch.spec 继续钉住"绝不禁用 `subagent-model-selection-settings`/`subagent`/`tool-subagent` 三行"——官方 preset 对该服务行是硬依赖）。

## 决策

1. 设置页**不再提供**官方授权清单（enabled/allowedModels）的编辑面；`OfficialAllowlistController` 与其 UI、统一保存参与者、locale 键全部移除。
2. 统一保存收敛为双命名空间：`subagent`（运行限制）→ `dsh-subagent-plus`。
3. 布局：运行限制作为候选清单**同一张卡**的顶部子区（官方 SubagentCard 单卡惯例：卡内分区用纯留白，不用边框/横幅切断）；接管声明文案并入「运行限制」ⓘ 悬停（原独立横幅删除）。合并卡的外壳在本插件自身命名空间失活时常渲染（T7 升级：页壳不消失），仅策略半区转状态行。
4. 版本 0.3.2（"内容变更必须先 bump 再 pack"；0.3.1 为未发布本地迭代，其条目并入本版 CHANGELOG）。

## 已知边界（显式声明）

- `respectExplicit=true` 且需要调整官方白名单的高级用户：插件启用期间官方页隐藏、本插件无编辑面——需临时在插件页关闭本插件（官方页回归）编辑，或手改 profile patch 的 `subagent-model-selection-settings` 行。文档（README/设置手册）明示。
- 候选清单为空且未配兜底时，轮询/随机仍以官方清单存量值为回落池（只读）；fresh 安装官方清单默认为空，行为与 0.0.2 一致。

## 影响

- 用户心智收敛为**一个清单**：候选模型清单＝子智能体模型选择的唯一入口；官方授权清单概念从产品面消失。
- 0001 决策 2 的"编辑面吸收"范围收缩为仅运行限制；0002 的"授权清单区迁入主布局"条目作废。
- 后续 by-name 策略（v0.4.0 构想）不受影响。
