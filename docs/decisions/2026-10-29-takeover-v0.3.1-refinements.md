# 0002 — 接管面打磨：页头完全接管开关、主页面统一保存、版本线续接（v0.3.1）

日期：2026-10-29 ｜ 状态：已实施（feat/v0.3.1-takeover）｜ 关联：[0001](2026-10-29-takeover-surface.md)（接管机制本体，继续有效）

## 背景

0001 交付的接管面遗留三点体验债：①「关闭插件」存在两个入口两种语义（插件页主开关=bundle 级、设置页软开关=仅停指派），用户难以分辨"谁在生效"；②接管卡独立于主设置卡之下、两区各自保存按钮，与官方页「运行限制在上、单保存页脚」的心智不一致；③ npm 上出现 0.3.0（2026-10-28 19:55 UTC，tag 推送触发 release.yml，早于 AGENTS.md 人工实测门 7 分钟），版本线与"从未发布"的认知冲突。另：用户诉求明确「关闭子Agent增强后官方接管回归」「运行限制在候选清单上方」。

## 决策

1. **D1 页头开关 = 完全接管开关（bundle 级）**。客户端经**探测式**获取的 `remote.pluginManager` 面调用 `setBundleEnabled('dsh-subagent-plus', false)`（`listBundles` 读态、`plugin-manager/changed`/`connection/reset` 刷新），与插件页主开关同态。**不进 `dsh.client.inject`**（硬依赖会在无该面的组合杀死整个 client 入口），探测失败降级为提示文案+插件页指引。确认条写明「本页将随之卸载；重新启用走插件页」；`applied` 卸载即生效、`restart-required` 留提示、拒绝/取消报可重试失败。软 `enabled` 字段不删不改语义，仅 UI 降级为高级首项「仅停用路由指派（保留接管）」——v0.0.2 存量 `enabled:false` 零迁移成本。
2. **D2 运行限制区上移 + 单一保存编排**。运行限制卡置于候选模型清单上方（镜像官方 SubagentCard 排版），授权清单区置于策略编辑器之后，独立接管卡删除。新增 `UnifiedSaveController`：按固定顺序（`subagent` → `subagent-model-selection-settings` → `dsh-subagent-plus`）逐命名空间提交，各走自己的修订栅栏；`unavailable`/`clean` 跳过不阻断，`blocked`（输入非法，官方单表单语义）与首个 `conflict`/`failed` **中止后续**并在页脚点名分区。页面外壳（页头/横幅/官方区/页脚）不受本插件命名空间失活门控——接管期间官方页隐藏，若外壳随自身 ns 一起消失会形成"两边都不可编辑"的死锁（T7 语义从"卡不消失"升级为"页壳不消失"）。
3. **D3 版本线续接 0.3.1**（不 unpublish、不 deprecate，等用户决策）。0.3.0 已是 registry 事实；0.0.3 低于已发布版本，任何 semver 区间都无法安装覆盖。`tests/manifest.spec.ts` 增两条守卫：package.json 版本 = CHANGELOG 顶部条目版本；版本不得低于已发布的 0.3.0。
4. **devDeps 对齐 0.2.1-rc.3**（用户桌面实际运行版；peer 区间本已覆盖），新增 `@deepseek-ai/dsh-plugin-manager` types 依赖仅为解析 `plugin-manager/changed` 事件键类型。

## 影响

- 用户心智模型收敛为单一开关语义：**开=接管（官方页隐），关=官方回（值保留）**；"仅停指派"成为显式的高级选项。
- 逃生门与已知边界不变（用户层 patch 恢复官方页；行级禁用 entry 的中间态文档化）。
- E2E：组合层断言（模块表反转）已在本轮无浏览器流程下留证（`dist-artifacts/e2e-v0.3.1/`）；浏览器 UI 全流程（含页头开关确认条）归 `docs/e2e-manual.md` §8.1 用户实测门。
- 后续 by-name 策略（v0.4.0 构想）不受影响。
