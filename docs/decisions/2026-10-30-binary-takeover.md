# 0005 — 纯二进制接管：插件页开关为唯一入口，官方授权清单零引用

日期：2026-10-30 ｜ 状态：已实施（feat/v0.3.1-takeover，v0.0.3 未发布迭代内）｜ 取代：[0002](2026-10-29-takeover-v0.3.1-refinements.md) D1 的页头开关与"软 enabled 保留"承诺、[0003](2026-10-29-candidate-list-replaces-allowlist.md) 的两条只读桥接

## 背景

用户审核（R7）指出产品叙事不自洽：宣称"候选清单 = 官方模型选择的完整替代"，页面却保留"仅停用路由指派"软开关（第三态）、页头开关与插件页开关双入口，且高级区仍有"自动采纳官方清单第一条"、合并卡仍有官方清单只读状态行——安装者无法回答"这到底是不是 100% 接管"。

架构核查（主仓 dsh-v0.2.1-rc.3 证据）：官方授权清单唯一的执行点在父侧 tool execute、spawn 之前，且只校验父模型显式传入的路由字段；子 Agent 实际请求经 `agent/request` 瀑布后无任何官方清单复核。因此"插件候选 ⊆ 官方清单"不是硬约束——唯一硬约束是路由在 LLM runtime 注册（failOpen 已预检），以及官方服务行保持加载（web preset 硬依赖，本插件从未禁用，`tests/takeover-patch.spec.ts` 机械钉住）。

## 决策（用户逐项裁定）

1. **安装即 100% 接管，二态互斥**：编辑面（官方页隐藏 + 运行限制同键直写官方 `subagent` 命名空间）与路由（候选清单/钉定/兜底为唯一来源）都归本插件；唯一关闭入口 = 左侧插件页 bundle 开关（关闭即官方页回归、值保留）。
2. **`enabled` 软开关删除**：schema、运行时门（request/request-error/pre-step）、boot 软化分支、高级区行全部移除；boot 校验恢复恒严格。存量 `enabled: false`（含用户桌面当时的暂停态）升级即翻转为接管——**已明示的行为翻转**。schemastery 对未知键宽容 merge，残键透传被忽略且永不写回（回归测试钉住）。
3. **官方授权清单零引用**：`autoRoute` 字段删除；`resolvePinRoute` 只认显式路由；`candidateRoutes` 只映射 `priority`；官方服务读取链（readSettings/ambient face/devDep）整删。官方服务行照常运行——零引用 ≠ 禁用。
4. **空配置 = 不指派 + 继承主会话模型**：钉定为空或清单为空（且未配兜底）时插件不干预，子智能体按官方默认解析继承主窗口会话模型（上下文隔离由官方委派机制保证）；页面明示提示，保存不被阻塞。`priority` 空清单的 degraded 特例删除，四种策略统一。
5. **页头开关删除**：与插件页开关同控 bundle 态（非第三语义），按"彻底单入口"裁定移除（takeover-switch 链、8 个 switch.* 文案键、plugin-manager devDep）。**代价（已接受）**：远程浏览器会话（非 loopback，配置区被官方冻结）失去页面内关闭面，只能改 profile 或本机操作。
6. **状态行随桥接删除**：官方清单只读状态行的存在理由（展示两条桥接所见）随桥接消失；保留只会暗示官方清单仍参与路由。

## 影响

- 用户模型一句话：装=接管，插件页关=官方回归，中间无第三态；未配置路由=不指派、继承主会话模型。
- 升级翻转三条（README 升级段明示）：`enabled:false` → 接管；钉定留空+autoRoute 采纳 → 不指派；空清单回落官方池 → 无候选（兜底/继承）。边角：存量 `enabled:false`+结构非法 yml 从惰性加载翻转为拒绝加载。
- 行级禁用（插件详情页行开关）仍不移除 bundle 层——宿主行为，逃生门为插件页重开或用户层 patch（e2e-manual §8.3 记载）。
- 运行限制区（官方 `subagent` 命名空间）不受影响：接管面里它本来就同键直写，与官方清单链无关。
