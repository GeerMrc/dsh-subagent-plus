# 0007 — 按名映射路由限定候选清单（B 方案）

日期：2026-11-12 ｜ 状态：用户裁定（2026-11-12"改 B 方案"），随 v0.0.4 发布 ｜ 取代：[0006](2026-11-byname-mapping.md) 决策 1 的 C 面（独立槽位/目录同源/允许清单外）与 UI 节相关句；0006 继续有效：决策 2/3/5/6/8/9、决策 4（除『清单外』动机句外）、**决策 7（校验二分——悬空 structural 项由本 ADR 决策 2 增补，其余枚举不变）**

## 背景

用户实测后裁定：插件应只维护**一张模型清单**——按名映射的目标路由必须来自候选清单，不再平行引用宿主完整模型目录（0006 的 C 面作废；决策史：B/C 两案同日提出、计划批准时落盘为 C，用户实测体验后于 2026-11-12 明确改判 B）。

## 决策

1. **映射路由唯一来源＝候选清单**：设置页两个路由下拉（行内改路由、添加映射）的 options＝候选清单条目与目录的联结行（`listedRoutesOf` 先例，跨行同路由合法——映射表只重名校验、不去重）；`routeFromValue` 对映射调用点参数化为候选清单表。运行时 `nameMap` 行仍自带 provider/model（配置形状不变），合法性由校验与防御层保证。
2. **悬空行（候选行被删后映射残留引用）＝structural 拒载**：保存拦截（红字点名行）＋boot 拒载，沿 0006 决策 7"配置无意义即拒载"精神；**运行时防御**：`decideByName` 对悬空行视为未命中落策略链（镜像"空 pin 不指派"先例 pin.ts resolvePinRoute），防运行中手编 yml 提交穿透（LivePinConfig 只拦 schema 异常的既有姿态不扩）。
3. **钉定策略处置（预设项 A，待用户批前可推翻）**：候选清单配置在钉定下持久但不可见；映射区**仍常显、已配行照常生效**（按名＞钉定解析链不变，0006 决策 2 保留）；钉定下"添加映射/改路由"禁用，提示切至轮询/随机/优先级策略编辑候选清单。
4. **记账 provider 子句保留**：0006 决策 4 的 nameMap provider 归因子句在严格 B 下冗余，保留为防御层（手编配置穿透时仍记账），注释更新。
5. **队友名 UX＝input＋原生 datalist 建议**（纯下拉在"Team 未跑时预配"场景不可用）：建议集＝客户端守卫 `ctx.get('sessions')` 读 `projectionsBySession` 中 `agentTeam` 投影聚合队友名（未装 Team bundle/无在跑队伍→空集静默降级）∪ 本表已用名；名字校验/红框/重名检测不变。
6. **分区改名**：zh「Team（队友名 → 路由）」/ en "Team (teammate name → route)"。
7. **布局单行化**：映射行改专用五轨 Grid `auto auto minmax(0,1fr) auto auto`（序号/名字 176/路由弹性≤240/档位≤120/删除），对齐候选清单行视觉几何；此前折行根因＝3 轨模板承载 5 子元素触发 Grid 隐式第二行（与宽度无关）。（**已被 [0015](2026-11-capability-derivation.md) 决策 3 取代**：删除挂序号 chip 悬停，五轨→四轨）

## 影响

- 语义损失（用户已知）：清单外映射场景作废；钉定用户需切策略编辑映射目标；16 行映射共享 ≤5 个候选路由（多行可指同一路由）。
