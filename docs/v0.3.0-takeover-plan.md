# v0.3.0 接管语义整改 — 语义冻结（内部治理文档，发布前归档删除）

日期：2026-10-29 ｜ 分支：feat/takeover-surface ｜ 状态：经用户终审的计划 T1–T7（两轮独立计划审核修订后批准）

本文件冻结本轮实现语义。任何实现中发现与本文冲突的事实，先修订本文并留痕，再改代码。

## T1 接管机制：patch disable 官方设置页插件行

- 插件 `cordis.patch.yml` 增加一行：`- id: ui-settings-subagent` + `disabled: true`（不加 name 守卫；该行由 web-app bundle 定义，id 全局唯一）。
- 生效语义：本插件启用（在 `dsh.profile.bundles` 内）→ 官方“子智能体”设置页（运行限制 + 模型选择双卡）不加载、插件页不可见；本插件禁用/卸载（`selectBundle(false)` 将包名从 bundles 移除，整层含 patch 消失）→ 官方页自动回归，配置值连续（同命名空间同键）。
- 弃用 slot 遮蔽方案：插件页清单层（deepseek-harness `config-ledger.ts:61`）用原始 `slots.entries` 而非遮蔽胜者视图，同 id 双注册会产生重复卡 + React key 冲突（独立审核 P0 证据）。
- 逃生门：用户层 `cordis.patch.yml` 永远可写 `{id: ui-settings-subagent, disabled: false}` 翻案（层序在所有 bundle 之后）；接管事实在插件页 overrides 列表可见。
- 只禁用 `ui-settings-subagent`（编辑面）。**绝不禁用** `subagent-model-selection-settings` 服务行（standard/ptc/cordis preset `modelSelectionSettings: true` 硬依赖，缺失即 subagent 工具整体消失）与 `subagent` 运行时行。

## T2 运行限制：同键读写官方命名空间，不复制运行时

- 我们的设置页新增“运行限制”section，经 `configForms.get('subagent')` 读写 `maxDepth`/`maxActiveSubagents`（官方 Volatile 字段）。
- 强制执行仍属官方 `SubagentRuntime`（spawn 期），与模型路由正交；我们只接管编辑面。单一事实源，禁用我们后官方卡回归值不丢。

## T3 官方授权清单：同键读写 + 语义重标注

- 我们的设置页新增“官方授权清单”section，经 `configForms.get('subagent-model-selection-settings')` 读写 `enabled`/`allowedModels`。
- 重标注文案要点：该清单供 per-call 显式选择（respectExplicit 开启时生效）与本插件 autoRoute/official 回落池使用；子代理实际路由由本插件分配策略决定。

## T4 开关即时性与存量语义

- bundle off → fiber dispose → 路由钩子即刻失效（hmr）。
- 存量子代：**下一次请求**起回官方解析；在飞请求不受影响。文档一律写“下一请求生效”，不写“即刻”。

## T5 接管横幅

- 我们的设置页顶部横幅：已接管并隐藏官方“子智能体”设置页；禁用/卸载本插件即完整恢复官方页面与行为。

## T6 maxTokens：路由变更时清除（对官方语义的有意偏离）

- `applyOverride` 的 route 变更分支清除继承的 `maxTokens`，交 LLM runtime 按新模型 `defaultMaxTokens` 物化（runtime 仅在 `maxTokens === undefined` 时物化）；effort-only 分支保留 maxTokens。
- **定性：有意偏离**官方 `resolveChildAgentOptions`（官方换路由明示保留 maxTokens、只清 effort）。理由：继承值绑定父模型容量，跨模型携带会溢出新模型上限且 runtime 无 clamp。README“已知行为”记录“父显式 maxTokens 不传播到被改路由的子代”；测试显式断言该丢弃。按新模型上限 clamp 记为技术债候选。

## T7 官方 ns 失活三分支（我们的卡不随 ns 抖动消失）

- 我们的设置页两 section 的可用性：双 ns 活跃（均可编辑）／单 ns 失活（对应 section 转 unavailable、另一 section 仍可写）／双 ns 失活（两 section 均 unavailable，页面其余部分正常）。
- 与官方卡的 `whileServed`（SOME 语义，任一 ns 存活卡就在）差异：我们的页面不因官方 ns 失活而消失——否则 ns 抖动会导致官方卡闪回、两页面并存。
